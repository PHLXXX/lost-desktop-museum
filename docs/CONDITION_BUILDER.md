# 条件构建器

线索和剧情触发使用声明式 `CaseCondition`，不执行脚本。可视化构建器与运行时求值器使用同一个联合类型。

## 节点

- `event`：玩家对目标执行了指定动作，如打开条目、查看元数据或日志详情。
- `all`：全部子条件成立。
- `any`：任一子条件成立。
- `clue`：指定线索已经发现。
- `clue-count`：已发现线索数达到阈值。
- `relation`：证据板存在指定关系。
- `trigger`：指定一次性触发器已执行。

示例：

```json
{
  "type": "all",
  "conditions": [
    { "type": "event", "eventType": "VIEW_METADATA", "targetId": "photo-platform" },
    { "type": "clue", "clueId": "clue-ticket-time" }
  ]
}
```

## 限制与校验

- 单棵条件树最多 5 层、30 个节点。
- 事件目标、线索和触发器引用必须存在。
- 线索之间不能形成循环依赖。
- 来源应用未启用时产生可达性警告。
- 条件编辑器提供 JSON 只读展开，正式数据仍由表单生成。

这些限制同时由草稿依赖分析和正式案件校验执行，不能靠手工修改工程包绕过。
