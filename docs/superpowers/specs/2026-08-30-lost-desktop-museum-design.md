# 《遗失电脑博物馆：最后一次登录》MVP 设计规格

日期：2026-08-30  
状态：用户已确认书面规格
仓库：`lost-desktop-museum`

## 1. 产品目标

交付一款可在浏览器完整游玩的中文悬疑调查游戏。玩家恢复一台被遗弃电脑的会话，通过文件、消息、邮件、照片、浏览记录、日历、回收站、系统日志和录音调查周屿失踪前的数字痕迹，整理证据并提交最终推理。

首个案件《没有出发的旅行》目标游玩时长为 15—30 分钟。MVP 必须具备完整内容、明确结局、12 条可达线索、证据关系构建、本地存档、自动化测试、静态部署和可验证的发布产物，不允许用空白窗口、占位内容或“Coming Soon”代替核心功能。

## 2. 范围与非目标

### 2.1 本次范围

- 原创 `ARCHIVE/OS 3.1` 启动界面和复古未来主义虚拟桌面。
- 十个桌面应用：我的文件、讯息、邮件、照片、浏览记录、日历、回收站、系统日志、证据板、设置。
- 文件内嵌的录音播放器和最终推理界面。
- 可拖动、分层、最小化、最大化、还原和关闭的窗口系统。
- 单案件数据模型、线索引擎、幂等剧情触发器、推理评分和版本化存档。
- 桌面端完整体验、小屏横屏提示、键盘可用性、减弱动画和系统音效设置。
- 单元测试、组件测试、Playwright 端到端测试、真实运行截图、中文 README、英文简介、CI、GitHub Pages 和 v0.1.0 Release。

### 2.2 明确不做

- 后端、账户、数据库、云存档、多人协作或外部 AI。
- 真实文件系统访问、真实加密、真实账号或真实品牌系统仿制。
- 复杂无限画布、自然语言自动评分、第二个案件或玩家编辑器。
- 运行时外链字体、图片、音频或其他联网依赖。

## 3. 体验与视觉

### 3.1 启动流程

首次加载依次显示 `ARCHIVE/OS 3.1`、异常关机检查、未完成会话、最后登录时间和用户。动画总长约 4 秒，可跳过。恢复会话和安全模式均进入桌面；安全模式关闭画面扰动并保持必要剧情文字。

### 3.2 桌面模型

桌面使用原创深蓝黑壁纸、灰蓝半透明窗口、琥珀黄提示、青色线索反馈与暗红危险状态。扫描线、颗粒和轻微撕裂只作氛围，不遮挡文本、不强闪烁，并遵循 `prefers-reduced-motion`。

桌面图标单击选中、双击打开；键盘 Enter 可打开已聚焦图标。任务栏显示运行中的应用、案件进度、声音与设置。窗口标题栏提供最小化、最大化/还原和关闭按钮；拖动时将标题栏限制在可视区域内。Escape 关闭顶层模态框。

视口低于桌面体验阈值时显示横屏/桌面设备建议，但仍允许继续进入，避免形成死路。

### 3.3 反馈原则

线索发现使用非阻塞通知和短提示音；密码错误、存档损坏和重置确认使用应用内对话框，不使用原生 `alert`。动态异常关闭时取消时钟回拨与画面扰动，但剧情消息仍显示。

## 4. 技术架构

### 4.1 技术栈

- React、TypeScript、Vite
- Zustand、Zod
- Vitest、React Testing Library、Playwright
- ESLint、Prettier、原生 CSS
- Web Audio API、localStorage

Vite `base` 在本地为 `/`；GitHub Actions 中从 `GITHUB_REPOSITORY` 的仓库名部分推导 `/<repo>/`。应用不使用需要服务器回退的 History Router。

### 4.2 模块边界

```text
case data ──> Zod validation ──> engine ──> Zustand stores ──> React features
                                      │              │
                                      └─ persistence ┴─ window manager
```

- `src/cases`：只保存类型和案件数据，不包含 React 行为。
- `src/engine`：线索判定、幂等触发、评分、存档与迁移等纯逻辑。
- `src/store`：游戏状态、窗口状态和设置状态的协调层。
- `src/features`：各应用与玩家交互；只发出调查动作，不复制案件判断。
- `src/components`：通用控件、原创 SVG 图标和反馈组件。
- `src/styles`：色彩、间距、排版、动效与全局可访问性规则。

一个文件只负责一个清晰职责，React 组件原则上不超过 300 行。

### 4.3 窗口管理器

每个窗口记录 `appId`、位置、尺寸、层级、最小化和最大化状态。打开已存在的单实例应用时聚焦原窗口；最小化保留状态；关闭移除运行实例。拖动使用 Pointer Events，同时支持鼠标与触控。最大化前保存正常位置和尺寸，便于可靠还原。

### 4.4 数据模型

`CaseDefinition` 聚合以下数据：文件夹与文件、聊天线程、邮件、浏览历史、日历事件、照片与元数据、线索、触发器、证据关系规则、推理问题和结算文本。核心类型包括需求指定的 `VirtualFile`、`VirtualFolder`、`ChatThread`、`ChatMessage`、`EmailMessage`、`BrowserHistoryEntry`、`CalendarEvent`、`PhotoAsset`、`PhotoMetadata`、`ClueDefinition`、`GameTrigger`、`EvidenceRelation`、`DeductionQuestion`、`DeductionResult` 和 `GameSave`。

案件启动时通过 Zod schema 校验。校验失败显示可恢复的档案损坏页，并阻止无效数据进入运行态。

## 5. 案件内容与线索路径

案件时间均采用虚构本地时间，跨应用严格使用同一时间线。十二条正式线索及最小发现动作如下：

| ID | 线索 | 必须执行的发现动作 |
| --- | --- | --- |
| C01 | 航班已取消 | 打开 HX217 取消邮件 |
| C02 | 取消后仍声称到机场 | 查看唐遥聊天中的时间对照提示 |
| C03 | 机场照片拍于 8 月 3 日 | 在照片查看器点击“查看元数据” |
| C04 | 搜索修改照片时间 | 打开对应浏览记录 |
| C05 | 告别信改为“离开周屿” | 在回收站依次查看或比较 v2、v3 |
| C06 | 林然生日为 11 月 19 日 | 打开日历中的“林然生日” |
| C07 | 创建隐藏用户 LINRAN | 查看对应系统日志或解锁账户配置 |
| C08 | LINRAN 从住所网络登录 | 查看 23:48 系统日志详情 |
| C09 | 这不是普通旅行 | 打开未发送给母亲的邮件 |
| C10 | 最后登录前房间仍亮灯 | 打开房东未读消息 |
| C11 | 酒店订单未取消 | 打开酒店订单文件或预订邮件 |
| C12 | 录音含公寓电梯提示音 | 播放录音并点击“辅助转写” |

每个发现动作产生结构化 `InvestigationAction`，线索引擎依据 `discoveryCondition` 解锁线索。重复动作不得重复弹出线索或累计事件。

`mirror.lock` 仅接受 `1119`。密码提示来自林然生日。成功后解锁身份草稿、LINRAN 账户配置和改名待办，并触发一次身份草稿相关事件。

两张机场 SVG 由本地原创矢量图构成；画面近似但文件属性不同。录音由 Web Audio API 程序生成室内底噪、双声电梯提示音和远处关门声，不下载音频文件。

## 6. 动态剧情

触发器采用唯一 ID，并在执行前检查 `triggeredEventIds`：

1. 发现 3 条线索：显示 LINRAN 离线消息。
2. 首次打开身份草稿：动态效果开启时桌面时钟回拨一分钟；关闭时仅保留文字提示。
3. 发现 8 条线索：向回收站注入“你正在寻找谁.txt”。
4. 提交最终推理：播放日志核对序列并显示 LINRAN 新会话与开放式结尾。

任何刷新、重复打开或存档恢复都不得再次执行已记录的一次性事件。

## 7. 证据板与最终推理

证据板自动呈现已发现线索。卡片可在有限画布中拖动，位置自动保存；可标记关键证据；可在两张卡片间建立“相互矛盾、相互支持、时间先后、同一人物”关系，并通过 SVG 绘制连接线。筛选条件覆盖人物、时间、地点和来源，删除关系不会删除线索。

发现至少 6 条线索后开放最终推理。玩家回答三个选择题，选取最多 6 条证据、至少一组矛盾关系，并可输入只保存在本地的个人推理。

评分为确定性纯函数：三个核心判断分别 25、20、20 分；六个推荐核心证据每项 5 分，最高 30 分；至少建立两组预定义正确矛盾关系得 5 分。自由文本不参与评分。结算按 90、70、50 分阈值显示四级结果，并列出已发现、已选择和遗漏的证据。

## 8. 状态、存档与恢复

`GameSave` 保存需求指定的全部字段，并以单一命名空间写入 localStorage。状态变化经过节流后自动保存，页面隐藏或卸载前立即保存。

读取流程为：JSON 解析 → Zod 校验 → 按 `saveVersion` 迁移 → 合并安全默认值。解析或迁移失败时保留原始损坏数据的内存诊断摘要，向玩家显示友好提示，并允许创建新存档；不得让白屏阻断游戏。

重置案件必须经过应用内二次确认，清除本案件进度并保留可访问性与音效偏好。重新调查从干净案件状态开始。

## 9. 错误处理与可访问性

- 案件数据错误、存档错误和音频不可用均提供可继续路径。
- Web Audio 创建必须由用户手势触发；不支持时保留静音播放进度和辅助转写。
- 主要按钮具有可读文本或 `aria-label`，焦点轮廓明显，模态框锁定并恢复焦点。
- 颜色不是唯一状态信号；文本对比度满足日常阅读。
- `prefers-reduced-motion` 和设置开关可关闭非必要动画。
- 所有筛选、密码和推理表单都支持键盘操作。

## 10. 测试与验收

### 10.1 单元测试

覆盖线索条件、触发器幂等、正确/错误密码、满分与缺证评分、存档往返、旧版迁移、损坏回退、12 条线索来源与条件完整性，并增加案件时间线一致性检查。

### 10.2 组件测试

覆盖启动进入桌面、图标打开窗口、最小化与任务栏恢复、照片元数据解锁线索、证据关键标记、少于 6 条线索时推理锁定，以及重置确认行为。

### 10.3 端到端测试

Playwright 在真实浏览器中完成启动、邮件、聊天、照片元数据、日历提示、1119 解锁、系统日志、证据板、至少 6 条线索、矛盾关系、推理和结算，并另测刷新恢复与重置。截图由实际页面生成到 `docs/images/desktop.png` 和 `docs/images/evidence-board.png`。

### 10.4 完成门槛

依次通过 TypeScript、ESLint、Vitest、生产构建和 Playwright；生产预览中人工检查所有应用、窗口交互、存档恢复、控制台、1280×720 布局及小屏提示。没有当前运行证据时不得声称对应项成功。

## 11. CI、部署与发布

`npm run check` 依次执行类型检查、lint、单元/组件测试和生产构建。CI 在 main push 和 pull request 上使用当前受支持的官方 Actions 与稳定 Node LTS 执行 `npm ci` 和 `npm run check`。

Pages 工作流在 main push 或手动触发时构建、上传 `dist` 并部署到 `github-pages` 环境，声明 `contents: read`、`pages: write` 和 `id-token: write`，并使用并发控制。

本地验证通过后创建公开仓库、设置描述与 topics，再启用 workflow 类型 Pages。只有部署实际成功并验证 URL 后才将地址写入 README 和仓库 homepage。CI 与 Pages 达到发布门槛后创建 `v0.1.0` 标签和 `v0.1.0 — The First Archive` Release；若 Pages 被权限阻塞，Release 不声称在线演示可用。

## 13. 决策记录

- 采用“数据驱动模块化架构”，不采用单体组件或首版插件平台。
- 采用单页面桌面状态机，不引入路由依赖。
- 使用 Pointer Events 自研轻量窗口拖动，避免大型 UI 组件库。
- 使用纯函数处理调查、触发、评分和迁移，以便测试与后续案件复用。
- 允许小屏继续游玩，但明确提示横屏或桌面设备体验更佳。

## 14. 最终验收定义

玩家从启动界面开始，在不访问外部服务、不修改代码的情况下，可以发现全部 12 条线索、解锁 `mirror.lock`、操作证据板、提交推理、看到结算与开放式结尾；刷新后进度恢复，重置后可重新调查。所有正式资源本地化，自动测试与静态构建通过，GitHub CI、Pages 和 Release 的状态均以真实远程结果为准。
