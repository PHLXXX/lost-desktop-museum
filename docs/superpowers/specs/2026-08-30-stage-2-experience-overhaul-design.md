# Stage 2 Experience Overhaul Design

状态：已批准（来自用户的阶段二执行规格）  
日期：2026-08-30  
方向：功能型档案操作系统（Operate）

## Design Contract

**THESIS** — 这不是一张展示“复古电脑氛围”的网页，而是一套玩家能持续操作、保存和恢复的档案系统；拒绝用巨大空白、霓虹线框和同构卡片代替信息架构。  
**OWN-WORLD** — 深墨蓝不透明工作面、暖灰内容纸面、1px 冷灰分隔线；琥珀只标记档案与警告，青色只标记在线与成功；窄工具栏、表格、树、状态栏和自绘线性 SVG 图标构成统一语法。  
**STORY** — 玩家从博物馆选择一台遗失电脑，启动案件快照，在可信应用痕迹中发现矛盾，把线索连成解释，最后返回博物馆留下完成状态。  
**FIRST VIEWPORT** — 首页左侧是博物馆标题和案件说明，右侧是一台编号展品的检查台；唯一主操作位于展品状态行末端，进度与本地存档紧邻而非悬浮成指标卡。  
**FORM** — 用户锁定的功能型档案系统优先于概念种子分配；种子 `b4fb1c81` 用于反模板校验，不覆盖已批准方向。  
**FINISH** — unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, and DESIGN.md

## Product Structure

`AppPhase` 是纯导航状态：`museum → case-detail → case-boot → investigation → deduction → result`。游戏存档独立保存案件进度；返回展馆不会重置，重新开始必须二次确认。刷新时默认进入博物馆，由案件卡的“继续调查”恢复。

## Information Architecture

### Museum

一条横向馆藏导航、一块案件展台和底部本地隐私说明。案件展台同时显示展品编号、状态、发现进度、最近保存时间和一个上下文主动作。没有存档显示“查看案件”；存在存档显示“继续调查”。

### Case detail

使用档案目录结构：左侧封面与案件编号，右侧包含对象、最后登录、调查目标、预计时长和本地存档状态。主动作根据存档为“开始调查”或“继续调查”，次动作为“重新开始”。

### Investigation

顶部案件状态条、中央工作区、底部任务栏。桌面图标以“实物档案工具”分组，但保留足够空白放置窗口。A/OS 打开系统菜单；Esc 按优先级关闭菜单/模态/帮助。

### Deduction and result

推理是明确阶段但仍由证据板进入；提交后进入 result，保留得分、证据/矛盾解释和返回展馆操作。避免把结果只作为窗口内临时模态。

## Visual System

- 界面字体：本地系统中文无衬线栈；数据、时间和编号使用本地等宽栈。不给产品增加外部字体依赖。
- 基础间距：4、8、12、16、24、32；窗口标题栏 36px，工具栏 38px，状态栏 26px，任务栏 48px。
- 圆角仅用于 2—4px 的机器外壳和浮层；应用正文使用直角分区。
- 阴影只表达活动窗口和模态层级；非活动窗口降低对比度，不使用模糊玻璃。
- 线索 toast 宽度约 300px，4 秒后消失，提供“查看”和关闭；状态不能只靠颜色。
- 动效只保留案件启动、窗口聚焦和线索入库三个功能时刻，并提供减弱动画等价状态。

## Window System

窗口使用有名称的 `role="dialog"`，但非模态；活动窗口有 `data-active`。默认尺寸：files 980×620、messages 860×580、mail 1020×650、photos 940×640、browser 900×560、calendar 880×600、recycle 820×520、logs 980×580、evidence 1100×680、settings 680×520。

标题栏拖动，双击最大化；边与角提供八向 resize handle。几何写入 GameSave v2，恢复时按当前 viewport 钳制。低于 1024px 的视口显示说明，新打开窗口默认最大化。

## Application Grammar

- 文件：路径/搜索/排序/视图工具栏，目录树，字段表格，预览与属性，底部项目状态。
- 讯息：联系人列表、未读与头像，时间线消息、附件和会话详情。
- 邮件：文件夹、邮件列表、阅读器三栏，草稿与状态字段清楚分开。
- 照片：日期分组缩略图、中心查看器、旋转/缩放、右侧信息与元数据。
- 浏览记录：语义表格包含时间、标题、域名、次数、设备；右侧详情解释记录来源。
- 日历：月视图与列表切换，事件选择后显示完整说明。
- 回收站：文件、原路径、删除时间、版本、保护状态；支持单项恢复与空状态。
- 日志：筛选工具栏、字段表格、右侧事件详情；数据字段使用等宽字体。
- 证据板：左侧线索库、中部画布、右侧详情；提供筛选、自动布局、撤销、缩放与重置视图。
- 设置：显示、声音、异常、扫描线、帮助与重置入口；设置变化即时保存。

## Persistence and Error Recovery

`GameSave` 升级到 v2，新增窗口几何、onboarding、临时便笺和可选 UI 偏好。v1 通过纯函数迁移，未知字段不影响加载。JSON 解析失败时原始值复制到 `archive-os:case-001:corrupt:<timestamp>`，主 key 恢复为新存档，并向玩家解释“已保留损坏副本”。

`SaveStatus = idle | saving | saved | error`。调查、设置、窗口和证据变化经过 350ms debounce 保存；显式保存立即刷新时间。页面离开前同步 flush。

## Accessibility and Responsive Behavior

桌面图标单击选择、双击和 Enter 打开、空白处取消；上下文菜单、系统菜单、模态和 onboarding 都管理焦点并支持 Esc。图标使用本地 SVG，所有控件有可访问名称。低于 1024px 不伪装成完整移动桌面：显示明确警告，最大化窗口，并保持关键流程可操作。

## Acceptance Evidence

以 1440×900 为主截图，补查 1366×768 与 1280×720；需要覆盖博物馆、案件详情、桌面、文件、邮件、照片元数据、系统菜单和证据板。最终必须通过类型检查、Lint、Vitest、生产构建、4 条 Playwright 玩家流程、无控制台错误、Pages 在线 HTTP 与界面内容检查。
