# 第四阶段编辑器架构审计

审计日期：2026-08-31  
审计基线：`main@90b7b01`，产品版本 v0.2.1

## 结论

当前仓库是通过测试的第二阶段版本，并不具备第三阶段所述的多案件与案件包基础。`CaseDefinition` 本身没有函数，适合继续数据化；但案件内容、运行时状态与组件都固定指向 `case-001`，Schema 仍大量使用 `z.any()`，不能直接支撑安全的可视化编辑器。第四阶段必须先补齐一组最小前置能力，再建设工坊。

## 当前案件数据结构

- `src/cases/types.ts` 定义单一 `CaseDefinition`，聚合文件、聊天、邮件、浏览、日历、照片、日志、线索、触发器与推理题。
- `src/cases/case-001/case.ts` 是唯一案件，数据集中但超过单文件可维护边界，并通过模块导入引用本地 SVG。
- `src/cases/schema.ts` 只严格检查少数字段；聊天、邮件、触发器和推理使用 `z.any()`，且硬编码 12 条线索与 3 道题。
- `InvestigationAction` 是有限的玩家行为联合类型；线索仅能绑定单一动作，无法声明 AND、OR、前置线索或关系条件。
- `GameTrigger` 使用 `kind` 分支，不含任意脚本，也没有 caseId 特判，但表达能力不足。
- `GameSave` 可序列化，但存储键固定为 `archive-os:case-001`。

## 可直接复用的模块

- React 19、Zustand、Zod、Vite、Vitest、Testing Library 与 Playwright 测试基础。
- 档案馆、案件生命周期、窗口几何、系统菜单、保存状态、独立应用与证据板视觉组件。
- 纯函数线索、触发器、评分与存档迁移模块的职责划分。
- GitHub Pages 子路径构建、PR CI、Chromium E2E 与本地设计变量。
- 不透明高密度 ARCHIVE/OS 视觉语言与本地资源约束。

## 必须调整的模块

| 问题 | 严重度 | 影响 | 修复方向 |
| --- | --- | --- | --- |
| 只有 `case-001`，组件直接导入 | 阻断 | 无法安装、切换或试玩用户案件 | 建立案件注册表与活动案件上下文 |
| Schema 使用 `z.any()` | 阻断 | 导入包无法建立安全边界 | 建立严格字段 Schema 与跨引用校验 |
| 存档键固定 | 阻断 | 多案件和试玩会互相污染 | 按 caseId 与 preview namespace 分区 |
| 单动作线索 | 阻断 | 无法实现条件构建器 | 建立声明式 `CaseCondition` 树 |
| 触发效果表达不足 | 高 | 无法安全配置剧情 | 建立白名单 `TriggerEffect` 联合类型 |
| 资源使用模块 URL | 高 | 无法打包用户资源 | 正式数据改用 `assetId`，Blob 存 IndexedDB |
| 无草稿模型 | 阻断 | 未完成工程会迫使正式 Schema 变宽松 | 新建独立 `CaseDraft` 与编译器 |
| 无引用图 | 高 | 改 ID 或删除会产生死引用 | 集中引用解析、原子重命名和阻止删除 |
| 无包格式与安全检查 | 阻断 | 不能导入、导出或往返 | 共用 ZIP 安全层与校验器 |
| 编辑器未拆包 | 中 | 档案馆首屏体积会显著增加 | `React.lazy` 加载工坊和重型模块 |

## 编辑器与运行时边界

运行时只接受严格 `CaseDefinition`，且只执行声明式条件与白名单效果。编辑器只操作允许缺字段的 `CaseDraft`。唯一正式通道为：

`CaseDraft → normalize → compile → validate → CaseDefinition → package → .ldmcase`

编辑器不能写入内置案件源文件。内置案件只可反编译为使用新 projectId 和新 caseId 的副本。运行时和编辑器复用同一严格 Schema、引用校验、条件求值与包安全代码。

## 草稿模型与正式模型

- `CaseDraft` 允许空标题、空内容、无推理等不完整状态，供自动保存与恢复。
- `CaseDefinition` 所有运行字段明确、无 `unknown` payload、无函数、无远程 URL、无 HTML。
- 编译失败返回路径化 `ValidationIssue[]`，绝不使用类型断言跳过错误。
- `decompileCaseDefinition` 生成可编辑副本；往返测试确保关键字段等价。

## 资源存储方案

- 工程元数据、草稿、历史摘要与 UI 状态存 IndexedDB；测试使用同接口内存实现。
- 图片、音频与文本 Blob 只存 IndexedDB，不进入 Zustand、localStorage 或工程 JSON。
- 资源由 `assetId`、SHA-256、MIME、大小、尺寸/时长与替代文本描述。
- Object URL 只在预览期间创建并及时撤销。
- `.ldmproject` 可携带全部工程资源；`.ldmcase` 只携带正式案件实际引用资源。

## 试玩隔离方案

- 试玩基于已编译的不可变快照。
- 存档 namespace 为 `ldm-preview:<projectId>:<revision>`，窗口状态同样隔离。
- 活动 PreviewSession 持有最近事件、线索、触发器和调试覆盖，不注册到正式档案馆。
- 返回工坊只恢复原编辑位置，不写正式最高分、完成列表或调查时长。

## 数据迁移风险

- v0.2.1 只有 `case-001` 固定存档键；迁移时必须保留原键并复制到新的 per-case 键，不能静默删除。
- 旧 `.lmdcase` 只影响扩展名识别，内容仍执行同一安全校验；导出永远使用 `.ldmcase`。
- 工程迁移是带备份的纯函数，失败后保留原始数据和最近快照。

## 性能风险

- 工坊、ZIP、资源哈希、音频与依赖图必须按需加载。
- 完整校验不随每次按键运行；字段校验即时，完整校验由按钮或防抖触发。
- 大资源 SHA-256 使用 Worker；大量列表使用分段渲染，Blob 不进入全局状态。

## 安全风险

- ZIP 路径穿越、重复路径、符号链接、压缩炸弹、伪装 MIME 与超限资源。
- HTML、脚本、远程 URL、SVG 第三方资源、外部跳转与任意效果类型。
- 多标签同时编辑、损坏工程覆盖、导出包含本地路径/试玩进度/未引用资源。

上述风险分别由安全解包限额、严格 Schema、白名单联合类型、引用校验、工程锁、快照和往返重新导入处理。

## 最终验收标准

1. 两个内置案件与用户案件使用同一注册、存档和运行引擎。
2. 非开发者无需编辑 JSON 即可从最小模板完成编辑、校验、试玩、导出、重导入和正常游玩。
3. `.ldmcase`、`.ldmproject`、`.ldmsave` 职责清晰；旧 `.lmdcase` 仅兼容导入并显示警告。
4. 草稿错误不能进入运行时，试玩不修改任何正式案件状态。
5. 导入包不执行代码、不加载远程资源、不接受危险路径或超限资源。
6. 工程刷新可恢复，自动保存失败时仍可导出工程备份，多标签默认只读。
7. 所有要求命令、E2E闭环、真实截图、CI、Pages和Release均有新鲜证据。
