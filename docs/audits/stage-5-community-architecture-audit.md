# 第五阶段社区架构审计

审计日期：2026-08-31  
基线：`main@0872e00`，v0.4.0 Archive Workshop

## 当前可复用模块

- `CaseDraft → CaseDefinition` 编译链、Zod Schema、引用检查、线索与推理可达性检查可以作为社区投稿和安装的统一语义边界。
- `importCasePackage` 已检查 ZIP 中央目录、路径穿越、重复条目、加密条目、符号链接、压缩比、扩展名、资源签名、SHA-256、未引用资源和远程内容，可直接用于下载后的第二次安全校验。
- `caseRepository`、`assetRepository` 已将安装案件与 Blob 放入 IndexedDB；多案件注册表和每案件独立存档允许社区案件离线运行。
- 档案工坊已经能够生成确定性 `.ldmcase`、往返导入验证、隔离试玩和工程快照。
- `downloadFile` 与资源管理器能够创建并及时释放 Object URL；现有React渲染没有使用 `dangerouslySetInnerHTML`。
- Vite和Pages已经稳定支持仓库子路径，社区模块可以使用动态导入保持首屏隔离。

## 社区索引数据流

```text
固定 VITE_COMMUNITY_REGISTRY_URL
  → URL边界规范化
  → 读取IndexedDB缓存并立即展示
  → 超过6小时或手动刷新时fetch
  → Zod严格解析index
  → 保存index和同步元数据
  → 案件详情按需解析并缓存
```

索引失败只影响“社区档案”。没有缓存时显示可恢复空状态；有缓存时继续显示上次目录。我的档案、内置案件、已安装案件、存档和档案工坊不依赖网络。

## 下载和安装数据流

```text
用户确认
  → 固定registry相对包路径
  → AbortController流式下载
  → 字节数检查
  → Worker SHA-256
  → registry哈希比较
  → importCasePackage完整安全校验
  → caseId/version/来源冲突检查
  → 展示验证摘要并再次确认
  → 写入案件、包Blob、资源和来源记录
  → 失败时按快照回滚并清理临时数据
```

完整包不会在详情打开时下载，安装也不会在第一次确认后自动完成。

## 更新数据流

更新检查只使用已缓存registry。更新前比较语义化版本、status、引擎范围和作者声明，再以当前GameSave中的线索、内容、解锁、恢复、关系、问题、窗口和事件ID对新Definition做实际兼容性分析。新包通过同一下载和安全链后，保存旧包与进度快照；安装或启动检查失败时恢复旧记录、资源和进度。最多保留两个旧版本。

## 缓存与离线策略

- index、detail、publisher和同步元数据保存在IndexedDB，不使用localStorage保存大型JSON。
- 有缓存先展示，6小时内不自动重复请求；手动刷新不受间隔限制。
- 截图只按需从固定社区源加载，安装后的正式运行只读取包内资源。
- 不引入Service Worker；新鲜浏览社区需要网络，已缓存目录和已安装案件离线可用。

## 信任模型

- “自动校验通过”只表示格式、资源、引用、哈希和执行边界通过，不表示内容、版权或主题绝对安全。
- `curated`仅表示维护者人工体验检查；没有人工检查时显示“未人工审阅”。
- 本地导入案件不能获得社区校验标签；来源元数据由安装器添加，不能信任CaseDefinition自报字段。
- 当前registry使用HTTPS和GitHub历史，但没有独立数字签名，因此客户端仍需执行SHA-256和完整包复验。

## 社区仓库结构

社区仓库是独立公开Git仓库，只接受`catalog/`源数据。Node脚本严格校验publisher、entry、截图和`.ldmcase`，再确定性生成`dist/registry/v1`、静态HTML、包和截图。`dist`不提交，不使用数据库、服务器、Cookie、分析SDK或客户端脚本。

## 双仓库发布顺序

1. 主项目生成并验证示例案件与测试fixtures。
2. 社区仓库本地校验、测试、确定性构建和静态站验收。
3. 创建并部署社区仓库Pages，验证registry、详情、publisher、截图、包和哈希。
4. 将真实registry URL写入主仓库GitHub变量和文档。
5. 完成主应用社区UI、安装/更新/投稿回归，合并主项目PR并部署Pages。
6. 线上验证真实社区安装后分别发布`registry-v1.0.0`和`v0.5.0`。

## 主要风险

- 跨数据库对象仓库无法天然原子提交：安装器必须使用可恢复快照和显式补偿回滚。
- GitHub Pages更新存在短暂传播延迟：客户端必须接受旧缓存并准确显示同步时间。
- registry条目是社区输入：所有字符串保持React文本渲染，外链和图片均经过固定源URL解析。
- 更新声明可能错误：必须以实际存档引用分析为准，不允许静默清除进度。
- 浏览器流式下载和Worker能力不一致：允许不确定进度与主线程哈希回退，但不能伪造百分比或绕过哈希。

## 验收标准

- 社区网络、索引、详情或截图任一失败均不会阻止本地案件和工坊。
- 哈希错误、包错误、内置ID冲突和blocked版本不能安装；失败后无半安装记录。
- 社区案件只能经过社区下载或手工本地导入出现，生产主包不预装示例社区案件。
- 更新前有兼容性结论和备份，回滚失败恢复原状态；卸载只清理目标案件资源。
- 收藏、评分、备注、进度和作者工程不上传；无账号、遥测、公开评分或下载量。
- 两仓库完整命令、CI、Pages和真实线上安装路径均有可重复证据。
